# Security review summary

| vulnerability | where found | fix applied | test that proves it | how Copilot helped (including any suggestion you rejected or corrected) |
|---|---|---|---|---|
| SQL injection | `SafeVault.Web/Data/UserRepository.cs` username lookup and insert | Kept SQL statements fixed and passed user values through SQLite parameters. No SQL is built from user input. | `InputAndRepositoryTests.TestForSQLInjection` checks attack strings are rejected, return no user, and leave the `Users` table intact. | Copilot's review did not identify a concatenated query. The parameterized repository pattern was retained; concatenating SQL or trying to sanitize an attack string would be less safe and was not used. |
| Cross-site scripting (XSS) | Razor Pages that render user-controlled values | Kept Razor's default output encoding and avoided `Html.Raw`. The validator allow-lists usernames and emails instead of stripping markup. | `InputAndRepositoryTests.TestForXSS` rejects script and event-handler markup and verifies HTML encoding removes raw angle brackets. | Copilot's review found no `Html.Raw` rendering sink. No sanitization-by-stripping suggestion was adopted; output encoding remains the rendering defense. |
| Cross-site request forgery (CSRF) | Login, registration, and logout POST handlers | Kept Razor Pages antiforgery validation enabled; logout is POST-only. No global antiforgery suppression is configured. | `AuthenticationIntegrationTests.LoginRejectsRequestsWithoutAntiforgeryToken` expects a 400 response without a token; login POST tests include a valid token. | Copilot confirmed Razor Pages antiforgery handling is active. The test verifies the behavior rather than adding redundant custom token code. |
| Brute-force password guessing | `SafeVault.Web/Pages/Login.cshtml.cs` and login endpoint configuration in `SafeVault.Web/Program.cs` | Added a per-source-IP fixed-window limit of five login POST attempts per minute, with HTTP 429 on excess attempts. | `AuthenticationIntegrationTests.LoginRateLimitsRepeatedAttemptsFromSameAddress` expects the sixth attempt to be rejected. | Copilot's security review specifically identified missing login throttling. We added server-side throttling rather than relying on client-side controls. The limiter is IP-based, so distributed guessing and shared-IP tradeoffs remain considerations for a production deployment. |
| Insecure authentication cookie flags | Cookie configuration in `SafeVault.Web/Program.cs` | Set cookies to `HttpOnly`, `Secure` always, and `SameSite=Strict`. | `AuthenticationIntegrationTests.CorrectPasswordSignsUserIn` checks the issued cookie includes `httponly` and `secure`. | Copilot's review prompted explicit cookie hardening; the integration test checks the actual response cookie. |
| Oversized input and BCrypt password truncation | Registration/login input models and `SafeVault.Web/Data/InputValidator.cs` | Set username, email, and password limits; require BCrypt passwords to be 8–72 characters and no more than 72 UTF-8 bytes before hashing or verification. | `InputAndRepositoryTests.EmailLongerThan254CharactersIsRejected` and `PasswordsOutsideBcryptSafeBoundsAreRejected` cover the bounds. | Copilot's review checklist called out missing length limits. We also constrained passwords by UTF-8 byte length so BCrypt cannot silently treat an overlong password as its truncated prefix. |

Failed logins for unknown users and incorrect passwords both display `Invalid username or password`. Login return URLs are restricted to local URLs.
